
Тестовая задача MSSQL — выдача следующего SSCC

Процедура dbo.sp_GetNextGS1SSCC выдаёт следующий уникальный SSCC
(Serial Shipping Container Code, серийный код грузового места GS1)
в виде (00) + 18 цифр.

На целевой базе, где таблица и функции уже есть, достаточно выполнить
sql/01_sp_GetNextGS1SSCC.sql. Там же, в шапке файла, — комментарии
к коду и пояснение решений.

Порядок у себя: 00_setup.sql → 01_sp_GetNextGS1SSCC.sql → 02_tests.sql.

Пояснение принятых решений

Уникальность. Не делал SELECT текущего счётчика и потом UPDATE.
Две сессии легко прочитают одно и то же значение и выдадут дубль.
Вместо этого один UPDATE: переменная и столбец заполняются в том же
операторе (SET @Serial = LastGS1SSCC = ...) под UPDLOCK. Вторая
сессия ждёт на строке и получает уже следующий номер.

SEQUENCE с CYCLE тоже решил бы задачу, но в задании уже есть
tbl_SSCC_Counter — работаю с ней. sp_getapplock не нужен, строка
счётчика и так сериализует вызовы.

Граница счётчика. Диапазон 0..999999999. После верхней границы
сброс на 0 (так разрешали в задании), через CASE, не через %:
так сразу видно намерение. Стартовое 0 в таблице — «ещё не выдавали»,
первый вызов отдаёт серийник 1. Ноль появится после оборота.

Ошибки. THROW, а не NULL/пустая строка: лучше пусть печать
упадёт, чем коробка уедет без номера. @SSCC обнуляется в начале и
в CATCH, чтобы клиент не получил старое значение OUTPUT-параметра.

Выходной параметр — NVARCHAR(22), длина совпадает с (00) + 18 цифр,
хвостовых пробелов нет (у CHAR они были бы). Ведущие нули серийника
не теряются: сборка через RIGHT(REPLICATE('0', 9) + ...).

Вызов

DECLARE @sscc NVARCHAR(22);
EXEC dbo.sp_GetNextGS1SSCC @SSCC = @sscc OUTPUT;
SELECT @sscc;  -- например (00)546025410000000016
